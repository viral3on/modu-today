# 읽을거리 CMS 운영 안내

## 작성과 발행

1. `https://modu.today/admin/`에 직접 접속합니다. 일반 메뉴에는 관리자 링크가 없습니다.
2. GitHub 저장소 관리자 계정의 fine-grained personal access token으로 연결합니다. 대상 저장소는 이 사이트만 선택하고, Contents 읽기·쓰기 권한과 Metadata 읽기 권한만 사용하세요. 짧은 만료 기간을 권장합니다.
3. 제목, 카테고리, 요약, 대표 이미지 주소/설명, 본문, 태그를 작성합니다. 카테고리 선택창에서 생활·IT·자동차·부동산·경제·주식·취미를 고를 수 있고, `직접 입력`을 선택하면 새 카테고리를 입력할 수 있습니다.
4. `임시저장`은 현재 브라우저에 저장합니다. 입력 중에도 자동으로 저장합니다. 다른 기기로 옮기거나 브라우저 데이터를 삭제하기 전에는 `초안 내보내기`로 JSON 파일을 보관합니다.
5. `미리보기`에서 표시를 확인합니다. 본문 작성 방식을 `기본 글쓰기` 또는 `HTML + CSS`로 선택합니다. HTML 모드는 문서 전체 또는 본문과 `<style>`를 붙여 넣을 수 있으며, 추가 CSS 입력칸도 제공합니다. 이미지(`<img>`), 표, 카드, 글자색과 반응형 배치를 지원합니다. 미리보기와 발행은 같은 정리 과정을 거칩니다. JavaScript, 이벤트 속성, 폼, 외부 임베드, 외부 스타일·폰트와 CSS URL 요청은 제외됩니다. CSS 선택자는 본문 범위로 제한되고 레이아웃도 격리됩니다.
6. `발행 검토` → `공개 발행`을 누르면 고유 URL이 생성됩니다. GitHub에 저장된 후 Vercel 배포가 완료되어야 공개됩니다. 화면에서 배포 완료를 확인하며, 지연되면 완료로 표시하지 않습니다.
7. 발행한 글을 목록에서 불러와 수정할 수 있습니다. URL과 최초 작성일은 유지되고 수정일이 갱신됩니다. 다른 편집기가 같은 글을 변경했다면 덮어쓰기하지 않고 충돌을 알려줍니다.

발행 내용과 수정 이력은 공개 저장소에 남습니다. 개인정보·비밀정보는 쓰지 마세요. 미발행 글 초안은 공개 저장소나 서버에 업로드하지 않습니다. 단, 직접 업로드한 이미지는 발행 전에도 공개 Blob 주소로 접근할 수 있습니다. 브라우저 저장소 자체는 OS 계정에 접근할 수 있는 사람으로부터 암호화된 보관함이 아니므로 개인 기기에서 사용하세요. 토큰은 탭 메모리에만 보관하며 로그아웃·새로고침 후 다시 인증합니다.

대표 이미지와 HTML 본문 이미지는 직접 만든 이미지 또는 사용 권한이 있는 HTTPS 이미지 주소/사이트 내부 주소를 입력합니다. HTML 예: `<figure><img src="https://example.com/photo.jpg" alt="이미지 설명"><figcaption>설명</figcaption></figure>`. 대표 이미지의 파일 선택·드롭과 본문 이미지의 파일 선택·드롭·Ctrl+V 업로드도 지원합니다. 업로드는 Vercel Blob에 저장하며 자세한 설정과 제한은 [이미지 업로드 안내](image-uploads.md)를 참고하세요.

## 기존 구조와 변경

- 기존 운영: 프레임워크 없는 정적 HTML, Python + GitHub Actions로 뉴스/아파트/로또/YouTube JSON 및 HTML 갱신, `main` 변경 시 Vercel Git 배포. DB와 웹 로그인은 없었습니다.
- 신규 발행 원본: `content/posts/<고유 ID>.json`. 스키마는 제목·카테고리·요약·이미지·본문·태그·작성일·최초발행일·수정일·발행 상태입니다. 이미 발행한 파일만 저장합니다.
- `api/editor.js`: 매 요청마다 GitHub 저장소 관리자 권한을 확인합니다. 동일 출처와 요청 크기 검사, 허용된 글 경로만 쓰기, 기존 파일 SHA 비교 후 단일 파일 커밋을 사용합니다. 서버 비밀키·신규 DB가 필요하지 않습니다.
- `lib/content.mjs`: 입력 검증과 안전한 Markdown 렌더러. 서버와 브라우저 미리보기에서 같은 코드를 사용합니다. HTML/CSS 정리는 `lib/html-content.mjs`에서 담당하며, 브라우저용 모듈은 빌드 때 묶습니다. `format`과 `css`는 선택 필드여서 기존 글·초안은 기본 글쓰기로 계속 열립니다.
- `lib/site.mjs`: 홈, 읽을거리 목록/본문, 도구, 뉴스의 정적 HTML과 SEO를 생성합니다.
- `scripts/build.mjs`: 기존 도구 HTML/JS/CSS/JSON을 `public/`에 복사하고 공통 메뉴를 삽입한 다음 편집 콘텐츠를 생성합니다. 기존 도구의 입력 ID와 계산·검색 코드는 보존합니다. 소스 코드/초안/문서는 배포 출력에 포함하지 않습니다.
- `update_news.py`: 메인 HTML을 재작성하지 않고 `news/data.json`만 갱신합니다. 전체 수집 실패 시 기존 데이터를 보존합니다.
- 기존 루트 `index.html`은 로또·SEO 보정 스크립트 호환을 위한 레거시 원본으로 남습니다. 실제 운영 홈은 매 배포 시 `lib/site.mjs`에서 생성됩니다. 루트 HTML을 편집해도 새 운영 홈에는 반영되지 않습니다.
- 신규 CMS 발행은 `main`의 글 파일만 갱신합니다. Vercel Preview에서는 해당 Preview의 Git 브랜치만 쓰도록 제한합니다.

## 안전한 전환과 되돌리기

기존 DB가 없어 DB 마이그레이션은 없습니다. 아파트·로또·YouTube 데이터 파일과 기존 수집 일정은 유지합니다. 뉴스만 별도 스냅샷으로 분리했습니다. 배포 설정의 기존 ignoreCommand는 유지했고 빌드/출력 위치와 관리자 보안 헤더를 추가했습니다.

스캐너 수집 코드와 중단 플래그를 보존합니다. 빌드는 스캐너 데이터/JS를 공개 출력에서 제외하고 두 기존 URL에 noindex 중단 안내만 제공합니다. 복구는 별도 검토 후 빌드 허용 목록과 공개 여부를 변경해야 합니다.

문제가 생기면 Vercel에서 직전 운영 배포로 되돌릴 수 있습니다. 저장소를 되돌릴 때는 이후 자동 갱신 데이터를 지우지 말고 해당 변경 커밋만 revert합니다. 발행 원본 파일은 삭제하지 말고 보관합니다.

## 검증과 운영 제한

- `npm test`: 관리자 인증/권한, 요청 위조·경로 조작 방지, 충돌 보호, 최초발행일 보존, 미리보기 렌더링, SEO, 배포 파일/데이터 보존.
- `python -m unittest discover -s tests -v`: 기존 아파트 저장, 로또 기록, 크롤링 생성 및 레거시 홈 보정 회귀 검사.
- `npm run build`: `npm ci` 후 정적 산출물과 사이트맵 생성. 공개 글의 잘못된 스키마는 빌드를 실패시켜 기존 운영 배포를 보존합니다.
- 새 글은 서버 생성 HTML로 발행되므로 JavaScript 없이도 본문과 메타 정보를 읽을 수 있습니다. 관리자·스캐너·외부 뉴스 목록은 noindex, 사이트맵에는 발행 글만 포함됩니다.
- 원본 글을 대량 생성하지 않았으며 초기 발행 글은 0개입니다. 메인의 글 영역은 명확한 준비 안내를 보여줍니다. AdSense 재심사 전 운영자가 직접 작성·검토한 유용한 글을 발행해야 하며 구조 개편 자체가 승인을 보장하지는 않습니다.
