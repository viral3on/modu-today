# 관리자 이미지 업로드

## 사용 방법

- 대표 이미지: `대표 이미지 업로드`에서 파일을 선택하거나 점선 영역으로 끌어다 놓습니다. 업로드가 끝나면 기존 대표 이미지 주소 필드가 채워지고 미리보기가 표시됩니다. 주소를 직접 입력하는 방법도 유지됩니다.
- 본문: `본문 이미지 추가`, 본문 영역 드래그앤드롭, 이미지가 있는 클립보드의 Ctrl+V를 지원합니다. JPG/JPEG, PNG, WebP만 파일당 **3MiB(화면 표기 3MB)**, 한 번에 10개까지 허용합니다. 대표 이미지는 한 개만 허용합니다.
- HTML + CSS 모드에서는 커서/선택 위치에 `<img src="…" alt="…" loading="lazy" decoding="async">`를 넣습니다. 전체 HTML 문서 끝에 커서가 있으면 `</body>` 앞에 넣습니다.
- 기본 글쓰기에서는 `![이미지 설명](https://…)`을 넣고, 미리보기와 발행 HTML에서 안전한 `<img>`로 변환합니다. 기존 Markdown 본문과 작성 방식을 유지합니다. 일반 텍스트 붙여넣기는 바뀌지 않습니다.
- 업로드 중에는 다른 글 열기와 발행 등을 잠시 잠급니다. 종료 후 원래 비활성 상태까지 복원합니다. 성공한 이미지 주소는 초안에 자동 저장됩니다. 여러 파일 중 일부만 성공하면 완료된 이미지는 유지하고 실패를 알려줍니다.
- 이미지 설명은 파일명으로 채우되 기존 대표 이미지 설명은 유지합니다. 발행 전 내용에 맞게 수정하세요. 업로드 이미지는 발행 전에도 공개 주소로 접근할 수 있습니다.

## Vercel 설정

1. `modu-today` 프로젝트의 Storage에서 **Public Blob** 저장소를 만들거나 기존 Public Blob을 연결합니다. Private 저장소는 블로그 이미지 직접 표시 용도에 맞지 않습니다.
2. 이미지 전용 저장소를 사용하는 경우 서버 환경변수 **`MODU_IMAGE_BLOB_READ_WRITE_TOKEN`**에 해당 저장소의 read/write 토큰을 연결합니다. 기존 환경변수를 덮어쓰지 않도록 전용 이름을 우선 사용합니다.
3. 기존 공개 Blob을 공유하려면 기존 **`BLOB_READ_WRITE_TOKEN`**을 그대로 사용할 수 있습니다. 전용 변수가 있으면 전용 변수가 우선합니다. 이 구현은 read/write 토큰을 명시적으로 사용하므로 `BLOB_STORE_ID`만 설정한 OIDC 연결은 충분하지 않습니다. 토큰은 브라우저 공개 변수에 넣거나 저장소에 커밋하지 마세요.
4. Production과 Preview 각각 사용할 환경에 변수를 설정하고 **새로 배포**합니다. 환경별로 다른 저장소를 연결해도 됩니다. 동일 저장소를 사용해도 `modu-today/images/production/`, `preview/`, `development/`로 경로를 구분합니다.
5. 기존 GitHub 관리자 인증 및 발행 설정은 그대로 사용합니다. 신규 DB/스키마 마이그레이션, GitHub 이미지 파일 커밋, 공개 Blob API 키가 필요하지 않습니다. 필요한 런타임 의존성은 `@vercel/blob`이며 빌드 명령과 출력 폴더는 기존 값을 유지합니다.

Vercel 서버 요청 크기 제한 안에 들어가도록 3MiB 이미지와 Base64/JSON 오버헤드를 포함해 약 4.2MB 이내로 제한합니다. `/api/editor` 함수의 최대 실행 시간을 60초로 설정하고 Blob 호출은 30초, 브라우저 업로드는 60초에 중단합니다. 브라우저는 동일 출처 API만 호출하므로 기존 관리자 CSP/CORS 정책을 넓힐 필요가 없습니다.

설정이 없으면 이미지 업로드에 저장소 연결 안내가 표시됩니다. 기존 이미지 URL 입력·글 작성·발행은 계속 사용할 수 있습니다.

## 저장·검증과 운영

`api/editor.js`의 `uploadImage` 작업은 기존 요청과 동일하게 Origin, POST/JSON, GitHub 토큰, 저장소 관리자 권한을 매번 검사합니다. 서버에서는 실제 디코딩한 크기, 확장자, MIME, JPG/PNG/WebP 파일 시그니처를 검사합니다. 전체 이미지 디코딩/재인코딩이나 바이러스 검사는 수행하지 않습니다. 파일명은 저장 경로에 사용하지 않고 UUID로 생성하며 덮어쓰기를 금지합니다. Blob 토큰과 외부 오류 원문은 응답에 포함하지 않습니다.

업로드는 글 발행과 별도 동작입니다. 취소한 글이나 교체한 이미지, 응답 시간 초과 직전에 저장된 파일은 저장소에 남을 수 있습니다. 다른 글에서 재사용할 수 있으므로 자동 삭제하지 않습니다. 불필요한 이미지 정리는 Blob 관리 화면에서 사용 여부를 확인한 뒤 진행하세요.

로컬에서는 서버 프로세스에 위 환경변수를 제공한 후 `npm run dev`를 실행합니다. 이 프로젝트는 `.env.local`을 자동으로 읽지 않으므로 Node 22의 `node --env-file=.env.local scripts/dev.mjs`를 사용할 수 있습니다. `.env*`는 Git에서 제외됩니다.

## 검증 명령

- `npm test`: 업로드 인증/파일 검증/경계 용량/오류/토큰 우선순위/이미지 렌더링 및 기존 CMS 회귀 검사.
- `python -m unittest discover -s tests -v`: 기존 아파트·로또·크롤링 검사.
- `npm run build`: 전체 정적 사이트 빌드.
- `npx playwright install chromium` 후 `npm run test:browser`: 실제 브라우저의 파일 선택·드롭·Ctrl+V·미리보기·초안 복원·발행 검사. 설치된 Chrome을 사용하려면 `CHROME_PATH`를 실행 파일 경로로 지정합니다.

브라우저 테스트는 실제 관리자 코드와 API 처리기를 사용하지만 GitHub/Blob 외부 연결만 로컬 테스트 서버에서 대체합니다. 실제 Blob 토큰 또는 운영 글을 사용하지 않습니다. 실제 저장소 연결 후에는 운영 관리자에서 작은 이미지 한 개를 올리고 주소가 열리는지 확인해야 합니다.

참고: [Vercel Blob 서버 업로드](https://vercel.com/docs/vercel-blob/server-upload), [Blob SDK 및 저장소 연결](https://vercel.com/docs/vercel-blob/using-blob-sdk).
